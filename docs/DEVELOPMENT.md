## 2. この作品固有のリスクと、その始末

**押下時間↔飛距離の理不尽感**を企画時から固有リスクとして挙げていた（SPEC §5）。
対策は「序盤は台座幅と会心窓を広く取り、難度カーブ側で絞る」。

公開前の健診（目付／UT）で、これが効いていることを数値で確認した。

- 飛距離 = `(72 + 300 × 押下秒) × 天候倍率`、押下0.15秒未満は跳ばない（誤タップ保護）
- **1段目に乗れる押下時間の幅は382ms＝溜めに使える全域(850ms)の45%**。適当に押しても半分近く乗る
- 8段41% → 20段30% → 40段6% → 60段3% と絞られる（20段以降は台座の揺れを最悪位相で差し引いた値）

**外した方向は落下の見え方で伝わる。** 音は届かない/跳びすぎで同一（`src/game.js:406` に理由つき）、
文字はリザルトまで出ないが、落下中カメラを止める処理（`src/game.js:1296`）に
「追いかけると『どこで外したのか』が画面から消える」と意図が明記されており、実機で意図どおり働いていた。

## 4. 踏んだところ

- **著者メールとブランチが既存2作と違った**。旧形式の noreply・`master`。push前なら書き換えは安全だが、
  push後は force push＝手作業になる。**公開の直前ではなく、公開の最初に突き合わせる。**
- **初版コミットに作業用の一時画像が混ざっていた**（`.tmp_ogp/`・2.8MB）。履歴から除いたが、
  filter-branch の最終チェックアウトで**作業ツリーからも消える**。OGPの元素材だったので、
  あとで文言を直すときに困った（`.git` のバックアップから復元）。**消す前に、他で使っていないか確かめる。**
- **OGPの文言が企画初期のまま**だった。「式札の道を、月まで」——式札は前作のモチーフ。
  仕様が「式札の飛び石」→「石の台座」に変わったのに画像が追随していなかった。
  文言は meta・README・画像・掲載文の4箇所にあり、**画像だけが機械で照合できない。**
- **プレビュー動画の規格を仮のまま引き継ぎかけた**。720×1280・15.9秒・冒頭1.5秒が帳。
  わいわいの正本は640²・14秒・冒頭からプレー画面（式札かさねの DEVELOPMENT.md に明記されていた）。
- **canon 立ち絵は白地や緑のクロマキー背景**の設定画で、そのままでは暗い画に使えない。
  ゲーム内のカットインを実映像から抜くほうが早くて正しい。

## 6. 先行2作の更新を移す（2026-08-31）

わいわいタウンの★4レビュー（08-29・しるばーさん）「ランキング機能が実装されたら嬉しいです」が出どころ。
下調べは `kitan-circle/data/articles/20260831-1640-tobi-port-diff.json`。
移植元は 御霊おとし `c6bb3fe`〜`6285a07`／式札かさね `8fe9e56`〜`8f1a877`。

### 6.1 番付を汚す穴が、先に見つかった（本作固有・最重大）

`#autoperfect` / `#automiss` / `#autoskip` / `#autowobble` は `autoTick()` から `begin()` を
直に呼ぶだけで、**試しモードの旗（`testMode`）を立てていなかった**。記録のガードは
`gameOver()` の `if (!s.test)` ひとつきりだったので、**自動プレイの結果がそのまま記録に書かれていた**。

式札かさねも同じ穴を踏んだが、本作のほうが重い。**あちらは80段が上限で理論最大 8080 に
頭打ちだったが、本作はエンドレスで `#autoperfect` に終わりが無い**——次の台座を正確に狙い続ける
だけなので段は青天井。そのまま番付を入れると、検証やPV撮影のたびに人が二度と抜けない点が載る。

判定は `canRecord()` / `canSubmitScore()` の2つに集約し、`playtest.js` に
**自動プレイ3経路の送信0回**と**人の手の夜の送信1回**を数える検証を足した。

### 6.2 番付の点は合成値 `到達段 × 1000 + 会心の連なり`

記録が2軸で、`getTopScores` は meta を返さないため、連を番付に出すには合成値が要る。
**桁が式札かさね（`段×100+浄化`）と違うのは、あちらに80段の天井があったから。**
本作は天井が無く、会心の連 ≦ 段 という関係しかないので、段が100を超えると `×100` は破綻する。
到達率は 40段6%・60段3%、設計上の想定は20〜30段（`src/game.js` の交代間隔の注）なので
`SANE_MAX = 999` へ人が届くことは無い。それでも桁は守りで塞ぐ（範囲外は送らない・載せない）。

### 6.3 セーブ保全は、式札かさねより素直に入った

**本作は記録を夜の終わりに1回しか書かない**ので、式札かさねで要った `visibilitychange` /
`pagehide` の取りこぼし対策は不要だった（あちらは1段ごとに書いていた）。
2キー（`tsukikage_best` / `tsukikage_best_combo`）を1キー `tsukikage_save` の束へ。
移行は「旧キーを読む → 書く → **書けてから**消す」。読めなかった夜は書かない。

### 6.4 結果の札が canvas なので、番付だけ DOM に出した

先行2作の結果カードは DOM だが、本作は canvas に描いている。順位の行は canvas に描き、
**押し所の矩形を `drawResult` が控えて `down()` が使う**（描いた場所と押せる場所を別々に持つと、
片方だけ直したときにずれる）。結果画面はどこを押しても次の夜へ行くので、
**順位の判定を再開より先に置く**。番付そのもの（他人の名前が並ぶ一覧）は DOM
——canvas に流し込むと指で送れず、読み上げにも乗らず、名前の長さで崩れる。

### 6.5 文字の大きさは canvas の指定ではなく実寸で決まる（本作固有）

この canvas は内部 480px を `min(100vw, 100vh*0.6667)` へ縮めて出す。
**375×667 の端末では 0.781 倍**になるので、canvas の 12px 指定は実寸 9.4px ＝
設えの正典の床（12px）を割る。床を満たすには **16px 指定**が要る（16 × 0.768 = 12.3px）。
今回足した順位の行と押し所はこの実寸で決めた（押し所 34px 指定 ＝ 実寸26.1px）。

**既存の canvas 文字（9px×5・10px×5・12px×4）は床を割ったまま残っている。**
直すと HUD と結果の札の字面が全体に変わるため、意匠の裁定として分けた。

### 6.8 検査の偽SDKは、本物の sdk.js を断ってから置く

`playtest.js` は `window.waiwai` を偽物に差し替えて送信回数を数えるが、
**本物の sdk.js を読ませたままにすると、本物が偽物を上書きしうる。**
破れた瞬間、検査の走行が本番の番付に載る（姉妹作『宵あらわし』が同日に踏みかけた）。

実測では `Object.defineProperty` の既定（`writable: false`）が守っていて上書きされていなかったが、
**相手の書き方次第で破れる**ので、リクエストごと断つようにした。

**断り方は `abort` ではなく空の200を返す。**`abort` だと `net::ERR_FAILED` がコンソールに出て、
「本体の誤りだけを見る」はずの検査が自分の仕掛けで赤くなる（実際に一度 exit 1 にした）。

**さらに、偽の応答にも CORS ヘッダが要る。**読み込み側のタグに `crossorigin="anonymous"` を
付けてある（COEP下で黙ってブロックされるのを避けるため意図的にそうしている）ので、
`Access-Control-Allow-Origin` を返さないと CORS で弾かれ、結局 `net::ERR_FAILED` になる。
**200を返しただけでは断てていない**——読み込み側の属性まで見て、それに答える形で返す。
