# 第三弾の仕様「溜め放ち・着地型」（2案マージ）

企画・設計担当が A案「着地型」と B案「飛距離型」を突き合わせて1本に決めたもの。
前提はタップ1系統・数十秒〜数分・腕前重視・キャラのアニメーション無し・ボイス無し・実作業8時間。

## 1. 結論 — A案「着地型」を採用

1. **中毒性**: 「じわじわ追い込まれる」感覚は、段を重ねるほど失うものが大きくなる連続性から生まれる。B案は1投ごとに緊張がリセットされる（B案自身が弱点として認めている）。溜め放ち型を選んだ根拠の数字（跳一跳・翌日継続65%／7日52%）は着地連続型そのものの実績で、A案だけがそれを引き継ぐ
2. **腕前**: 「到達◯段・会心連続◯」は既存2作の「段」の言葉と地続きで、Discordに貼る数字として最強。B案の飛距離は0.9秒往復ゲージの目押し1軸に痩せやすい
3. **長編への部品**: 御霊ごとの跳び方の癖が、キャラ切り替えで攻略する長編の1本目になる

## 2. B案からの移植（4点）

| 移植 | 効きどころ |
|---|---|
| **ノーチャージ保護**（押下0.15秒未満は跳ばず、その場で震えてキャンセル） | 誤タップ即死を消し、A案最大の弱点「理不尽感」を先回りで潰す |
| **リザルト札絵のランク連動**（称号ランクに応じ fuda 01〜10 を背景に） | 未使用fudaの消化＋記録更新の視覚報酬。差し替え1本で済む |
| **節目カットイン** | 未使用cutinの初消化。再生は御霊おとしの cloneNode 方式を流用 |
| **`#autoperfect` と「SE9種は既製支給＝200Hz問題の対象外」の整理** | A案のSE合成前提は誤りだった。検証と音実装の無駄を削る |

**両案が割れた点の裁定**

- **癖の粒度 → A案の2タイプ（軽い/重い）**。8時間で作り切る条件が長編への部品化より上位。チューニング面積が半分で済み、鎧か忍装束かの見た目で説明が済む（チュートリアル無しの条件に適合）。五行5パターンは長編で拡張する
- **区切り → A案の節目演出**。段を継ぐ型に「3投1組」は接げない。跳一跳の中毒の核＝一本の緊張を切らないことを優先。ただしBの「自己ベスト更新を即見せる」だけリザルトに移植

## 3. 仕様

- **遊びの芯**: 長押しで力を溜め、離して跳ぶ。宵闇に浮かぶ**式札の飛び石**を渡り、何段先まで届くかを競う。世界観は式札かさねの続き——「架けた札の道を、御霊が渡って月へ向かう」
- **画面と操作**: 縦持ち1画面・論理480×720。ちび御霊（静止画）が金縁の式札形台座に立つ。次の台座は距離・幅ランダムで先出し表示。**長押し**＝足元に金のリングゲージ（押下時間∝飛距離）。**離す**＝放物線tween（高さは影の伸縮とY座標のみ・アニメ無し）。着地は中央＝会心／端＝辛勝／外＝ミス。失敗3種（ショート／オーバーシュート／踏み外し）＋ノーチャージ保護
- **コアループ**: 立つ→溜め→放つ→着地→次へ。1跳び約2〜3秒、平均20〜60段で力尽きる。ミス即リザルト、リトライ1タップ
- **難度・スコア・段位**: ①距離ブレ拡大 →②台座幅縮小 →③左右オフセット →④会心窓の漸減（下限は切らない。ゼロサム化すると運ゲーになる）。スコア＝**到達段数**＋**会心連続**。称号5種、localStorage永続。**5段ごとに御霊交代（34キャラ巡回）**
- **使う素材**: ちびシート2頭身 **34点**（跳躍本体・全消化）／顔アイコン **34点**（交代予告・リザルト）／cutin **34点**（節目演出）／fuda ランク01〜10連動でリザルトに1枚／track_jacket **2点**（タイトル・リザルト背景）
- **音**: start=開始／count=着地刻み／zan=会心／kiwami=節目段／combo=会心連続（音程上昇）／whiff=ショート落下／bomb=オーバーシュート／fukaku=踏み外し／end=リザルト。BGMは咲耶「無用の火」ループ、タイトルのみ於兎「あかるい係」
- **御霊ごとの癖**: 軽い/重いの2タイプ。**風魔勢8キャラ＝重い**（弧が低く直線的・溜め要求が多い）、他26キャラ＝軽い（ふわっと高い弧）。見た目（鎧 vs 忍装束）が説明を兼ねる
- **終わり方**: エンドレス。背景の月が最高到達段に応じて満ち、**50段で満月の見せ場**（続行可・別格称号「満月渡り」）。「満月は到達点、記録はその先も伸びる」で、式札かさねの教訓とエンドレスを両立

## 4. 公式演目・既存2作との違い

- **跳ね兎**: 固定間隔の反射リズム。本作は長押しで自分で距離を作る力加減の遊び
- **射的**: 照準の精度。本作に照準は無く、押下時間だけが結果を決める
- **筆返し**: 継続的に打ち返す反射。本作は「離す一瞬」に凝縮した一回性の判断
- **御霊おとし**: 物理落下の配置パズル。本作は自分が跳ぶ。エンドレスは重なるが操作系と緊張の質が別
- **式札かさね**: 迫る札を「止める」目押し。本作は力を「作る」溜め加減。世界観上は続編として接続

## 5. 実装の勘所と落とし穴

既存2作から効くもの: 単一HTML＋遅延アセット／iOS対策（ダブルタップズーム抑止・`gesturestart`）を最初のコミットに／開始・リトライ後700ms入力停止／canvas流用描画は `beginPath` で引き直す／Artifact音源は `atob`→`decodeAudioData`（`fetch(data:)` は全滅。合成フォールバックの静かな事故に注意）／演出は3点集中（タイトル・満月・リザルト）／カットイン再生リセットは `cloneNode`。物理エンジンは不要（固定重力の二次関数のみ）。

**固有のリスク＝押下時間↔飛距離の理不尽感**。対策: ①跳一跳実証の線形写像を出発点に係数1つで調整 ②序盤は台座幅・会心窓を広く取り、難度カーブ側で絞る ③`#stat` ハッシュで「押下時間と着地偏差」をログし、体感でなく分布で追い込む ④難度パラメータは1箇所の表に集約。

## 実プレイを受けた設計変更（2026-08-25）

仕様書の初版から、次の3点を変えた。判断の経緯は
`kitan-circle/employees/game-dev/growth-log.md` に残っている。

### 1. 御霊ごとの癖 → 天候

初版は「風魔勢＝重い」でキャラごとに距離を変えていたが、**体感できない**うえ、
射程を詰めると終盤の間合いに届かず詰む問題があった。代わりに**天候**を置いた。

| 天候 | 距離 | 表示 |
|---|---|---|
| 月夜 | ×1.00 | いつも通り |
| 追い風 | ×1.16 | 伸びすぎる |
| 雨 | ×0.86 | 伸びない |

8段ごとに変わり、上部の帯に名前・効き・目盛りで常時出る。切り替わった瞬間だけ中央に短く出す（遊びは止めない）。
天候は**画面を見れば分かり、説明が要らず、キャラ間のバランス調整も要らない**。
キャラごとの癖は、将来の長編（キャラを切り替えて攻略する型）に回す。

### 2. 着地位置がそのまま次の起点になる

初版は着地後にキャラが台座の中央へ寄っていた。いまは**着いた場所にそのまま立つ**。
次の跳躍はそこから始まるので、「台座のどこに乗ったか」と「台座の幅」の2つが効く。
このため、キャラごとの味付けが無くても考慮要素は足りている。

### 3. カメラは跳躍中に動かさない

跳んでいる間にカメラが着地先へ寄ると、右へ跳んでいるのに一度左へ流れて見える
（弧とカメラの移動が混ざるため）。**跳躍中はカメラを止め、着地してから寄せる**。

### 見た目

- 台座は**石垣を切り出した意匠**（上面＋布積み2段）。忍者の里の石垣に寄せた
- 背景は遠景（山並み・街灯り）と近景（霞・夜桜）のパララックス。**鏡張り**で継ぎ目を消す
- 着地の波紋（会心は金）、5段ごとの御霊交代（顔アイコン＋名前）

### 称号を10種から5種に減らした（声に合わせた）

| 段 | 称号 | 声 |
|---|---|---|
| 0〜9 | 宵の踏み出し | r0 |
| 10〜21 | 夜歩き | r1 |
| 22〜37 | 月見の足 | r2 |
| 38〜49 | 闇夜の跳ね手 | r3 |
| 50 | 満月渡り | r4（満月成就） |
| 51〜 | 満月渡り | **r5**（満月を越えて落ちた） |

### 満月成就の儀を入れた（50段の見せ場）

企画の「50段で満月の見せ場」は**背景の月が満ちるだけ**で実装されていて、到達しても何も起きなかった。
`moonRite()` を追加。**1.9秒・その間は入力を止める**（`lockUntil`）。

- 画面を0.90まで沈め、月を中央上に大きく描き直して光暈を広げる
- 金の粒46個が下から立ち上る
- 下段に「満月成就」（金グラデ・字間広め）＋「五十段の高みで、満月に逢えた」「この先も、記録は伸ばせる」
- 音は `kiwami` → 0.62秒後に `fukaku`
- 儀の間はHUDとフローターを止める（`rite.t > 0` で抑止）。50段の節目フラッシュもこちらに置き換える

**続行可**は企画どおり。「満月は到達点、記録はその先も伸びる」を字幕でも言い切る。

### 50段より先の難度 — 台座の揺れを速くする

幅・間合い・会心窓は50段までに下限へ達する設計なので、**そのままだと51段以降は難度が上がらない**。
台座の左右の揺れ（`driftFor`）に上乗せする形で伸ばした。**幅は変えない**（下限を切ると運ゲーになる、の原則は維持）。

| | 50段まで | 51段以降 |
|---|---|---|
| 揺れ幅 | (段-12)×0.85、上限26px | 26 + (段-50)×0.22、上限38px |
| 揺れの周期 | 900ms 固定 | 900 - (段-50)×9、下限420ms |

上限に達するのは約105段（幅）／約103段（速さ）。そこから先は純粋な集中力の勝負になる。

### 儀と御霊の交代が重なったら（2026-08-26 オーナー確認）

**通常プレイでは重ならない。**御霊の交代は4段ごと（`SWAP_EVERY = 4`）で、儀に入る段は50か51
（一つ飛ばしで49→51と届く場合）。どちらも4の倍数ではない。天候（8段ごと）も同様。
ただし**試しモードの「+10段」では重なる**（例: 40→50は交代の境も跨ぐ）。

重なったときの決まりは**儀が全面に優先**。実装は3点:

1. `moonRite()` の頭で、走っているカットインを畳む（`swap.t = 0`）。
   沈めた画面の下から帯と立ち絵が透けるため。途中まで見えていたぶんで打ち切る
2. `showSwap()` は儀の最中なら `swap.pending` に積むだけにする
3. `drawRite()` が終わった瞬間に、積んだカットインを出す

**カットインを黙って捨てない**のが要点。捨てると「誰に代わったのか分からないまま」次の段に入る。
`land()` とテストバーの両方で、`moonRite()` を交代の判定より**先**に呼んでいる（順番が逆だと1.が効かない）。

### 一つ飛ばしで50段を跨いだとき（2026-08-26 オーナー確認）

**49→51と飛び越しても儀は出る。**判定は「跨いだか」で見ている（`prevStep < 50 && s.step >= 50`）。
検証済み: 49段で着地点を2つ先の台座に合わせると `play/49段 → play/51段/儀` と入る。
`moonPhase` も `step/50` の上限1で満ちるので、背景の月も満月になる。

この場合の称号は「満月渡り」、落ちたときの声は **r5**（51段以上）。
ちょうど50段で止めた回だけが r4 になる。

**入力止めは自動プレイにも掛ける。** `autoTick` は `down()` を通さず `s.charging` を直接立てていたため、
儀の最中も跳び続けて `play/51段/儀 → play/52段/儀` と進んでいた（実プレイは `down()` の
`lockUntil` で止まるので影響なし）。検証が実物とずれるので、`autoTick` にも同じ判定を入れた。


## 12. レビュー反映（2026-08-26）

企画・設計担当のレビュー（`data/articles/20260826-0956-tsukikage-review.json`）の上位5件を反映した。

### 会心の音を作り替えた（オーナー裁定）

琴のワンショット（200Hz・鳴り1.2秒）は、**跳ぶ音（8.5kHz・鳴り0.14秒）より低くて長く**、
高低が逆転していて報酬に聞こえなかった。連による音階の切り替え（`koto` / `koto_high`）もやめて一種に統一。

**最初は琴を5倍速に上げて詰めたが、これは失敗だった。** 元の `koto.m4a` は単音ではなく
**5音のフレーズ**（0.15/0.30/0.55/0.80/1.05秒に立ち上がりがある）で、速くして時間で切ると
必ず音符の途中で切れる。さらにピークを-1dBに正規化していたため、**跳ぶ音より7dB大きかった**。

**公式配布の `combo.m4a` に差し替えた**（2776Hz・単音・鋭い立ち上がりから0.40秒で減衰しきる）。
用途としても「連」の音で、会心＝連が伸びる場面に一致する。

| | 旧 koto | 失敗した自作 | 現 combo |
|---|---|---|---|
| 主要周波数 | 200Hz | 985Hz | 2776Hz |
| 鳴り | 1.20秒 | 0.32秒（音符の途中で切断） | 0.36秒（自然減衰） |
| 鳴った時の音量 | — | **-11.4dB** | **-18.3dB** |

加工は「減衰しきった0.33秒から0.11秒かけて畳む」＋「+2.5dBで他のSEと揃える」だけ。
**音符の途中を切らない。** `koto` / `koto_high` は削除した。

### 効果音の音量は「鳴った時」で揃える

ピーク正規化だけでは揃わない。短く明るい音はピークが同じでも体感で大きい。
**0.1秒窓のRMS × `se()` の第2引数**を「鳴った時の音量」として並べ、これを揃える。

| 音 | 鳴った時 |
|---|---|
| 跳ぶ zan | -18.1dB |
| 会心 combo | -18.3dB |
| 空振り whiff | -18.3dB |
| 夜明け end | -17.1dB |
| 満月成就 kiwami | -13.6dB（ここだけ意図的に大きい） |

### ダッキング — 経路が2本あることを忘れない

`voice()` が `bgmGain`（WebAudio＝Artifact経路）しか下げておらず、**主配信の Pages 版では効いていなかった**。
`bgmVol()` で `bgmEl`（HTMLAudio）と `bgmGain` の両方を吸収し、効果音も専用バス `sfxBus` に集めて
台詞中だけ `SFX_DUCK = 0.45`（約 -7dB）に沈める。

**`sfxBus` は AudioContext を作る時点で一緒に作る。** 最初の効果音が鳴るまで作らない書き方だと、
帳と同時に鳴る開始の台詞のダッキングが空振りする（実測で確認した）。

検証は `window.__tsukikage.audio` で数値で見る（`{bgm, path, sfx, ducking}`）。実測:

| | BGM | 効果音 |
|---|---|---|
| 台詞の最中 | 0.07 | 0.405 |
| 台詞のあと | 0.16 | 0.900 |

### 記録を2軸にした

### 実装と外向きの文を揃えた

README の「5段ごとに交代」「風魔勢は重い」「音源9種」、SPEC の「34体を巡回」はすべて実装と違っていた
