## 作り方

ElevenLabs の**無料プランは API からライブラリボイスを使えない**（402 paid_plan_required）ので、
**ブラウザUIから**生成する（式札かさねと同じ。Claude in Chrome での自動操作も可）。

1. ElevenLabs の Text to Speech を開き、**モデルは Eleven v3**
2. 声を **Mini** にする。同名の声があるので、UIの「声のIDをコピー」→ `pbpaste` で
   `hO2yZ8lxM3axUxL8OeKX` と一致することを必ず確認する
3. 台詞の**先頭に推奨タグ**を付けて入力する。例:
   `[japanese][calm][mysterious] 月への道、開きました。……ゆるりと、まいりましょう`
4. 生成 → ダウンロード（mp3）
5. `assets/voice/shiori_<キー>.m4a` として置く（変換は下記）

```bash
# ダウンロードしたmp3を、ゲームで使う形に変換する
ffmpeg -y -i ~/Downloads/<落としたファイル>.mp3 -vn -map 0:a -c:a aac -b:a 96k \
  assets/voice/shiori_start.m4a
```

置いたら `node scripts/build-dist.js && node scripts/build-artifact.js` で取り込まれる。
**音源が無いキーは黙って鳴らないだけ**なので、1本ずつ足していける。

## 音量の設計

`docs/MEDIA.md`（シリーズ共通）の原則どおり **声 > 効果音 > BGM**。

- 声: 1.0（そのまま）
- 効果音: バス `sfxBus` で 0.9。**声が鳴っている間は 0.405（約 -7dB）まで沈める**
- BGM: 0.16。**声が鳴っている間は 0.07 まで下げる**（`duck()` が自動で戻す）

**BGMの経路は2本ある。** Pages版は HTMLAudio（`bgmEl.volume`）、Artifact版は WebAudio（`bgmGain.gain`）。
`bgmGain` だけ下げていた時期があり、**主配信の Pages 版でダッキングが効いていなかった**（2026-08-26 修正）。
`window.__tsukikage.audio` で数値を見れば、聴かなくてもどちらの経路かと沈み具合が分かる。

式札かさねでは「SEが声とほぼ同じ大きさで並んでいた」という取りこぼしがあったので、
ボイスを入れたら**必ず実機で通しで聴く**こと。

## つまずいた点（次に作るときのために）

### 「……」は「テンテンテン」と読まれる

最初の台詞に三点リーダを入れたら、**そのまま「テンテンテン」と発話された**（8.6秒に膨らんだ）。
Whisperの文字起こしで発覚。**間を置きたいときは句読点で作る**か、v3のタグを使う。三点リーダは書かない。

### かな書きが逆効果になることもある — 「まんげつわたり」→「まんげつあたり」

r4 をかな書き `まんげつわたり` で作ったら、**「まんげつ**あたり**」と読まれた**。
「まんげつ」に続く「わ」が飲まれて「あ」になる。かなにすると音の切れ目の手掛かりが消えるため、
**むしろ崩れやすくなる語がある。**

直し方は**漢字に戻して、助詞を足す**: `満月渡り、と。つきに、届きましたこと`
（「渡り」は漢字ならわたり以外に読みようがない。「、と。」は公式見本
「第一夜、と。」と同じ栞の口調でもある）。これで2テイクとも「満月渡り」になった。

r5 は最初からほぼ同じ語を含んでいて、テイク1は「渡り」・テイク2は「辺り」に割れていた。
**この語は元々コインの裏表**で、かな書きはその確率を悪くしていた。

かな書きが効くのは「常用外漢字が読めない」場合（頁→ページ）。
**読めるのに崩れる場合は、表記ではなく前後の文脈で固定する。**

### 称号はかな書きで読みを固定する

「夜歩き」が **「いえあるき」** と読まれた（文字起こしで検出）。「月への道」も読みが怪しかった。
**画面に出す表記（漢字）と、読ませる文字列（かな）を分けてよい。** 声は かな、画面は漢字でいい。

- 夜歩き → `よあるき`
- 月見の足 → `つきみの足`
- 闇夜の跳ね手 → `やみよの跳ね手`
- 満月渡り → **`満月渡り`（漢字のまま）**。かな書きは逆効果だった（下記）
- 律儀な方 → `律儀なおかた`（「かた」か「ほう」か割れるので、送りをかなにする）
- 一頁目 → `一ページ目`（栞は「頁」を使うキャラだが、読みが不安定なのでカタカナに）

### 生成は30〜40秒かかる

「音声を生成」を押してから2テイクが揃うまで、体感で30〜40秒。**待たずにダウンロードを押すと空振りする**
（波形がグレーのうちは未完成）。自動操作するなら、待ち時間を長めに取るか、波形の色で判定する。

### 後処理は `scripts/prep_voice.py` に集約した

前後の無音を落とし、ピークを-1dBに揃えて m4a にする。台詞ごとの音量差がこれで消える。
v3は末尾に無音が付くことがあり、`r4` は 6.8秒 → 5.0秒 まで削れた。

### v3は「鳴っている途中で」終わることがある

`r1` の「悪くない足どりでした」の最後の **「た」が母音の途中で切れていた**
（振幅0.25のまま10msで0に落ちる＝プチッと止まる）。
オーナーが r2 の終わり方を尋ねたのをきっかけに全7本を測って見つけた。
文字起こしは通る（言葉は全部入っている）ので、**ASRでは検出できない**。波形を見るしかない。

`prep_voice.py` に検査を入れた。**鳴っている最後の瞬間**（無音を落とす前の `idx[-1]`）の
直前10msを見て、ピーク比12%を超えていたら50msのフェードで畳む。
検査する位置を「余白を足したあとの終端」にすると、そこは無音なので永久に発火しない
（最初そう書いて空振りした）。

| 声 | 元の切れ際 | 処理 |
|---|---|---|
| r1 | ピーク比28% | フェードで畳んだ |
| r5 | ピーク比15% | フェードで畳んだ |
| 他5本 | 2〜5% | そのまま |

**再エンコードでピークが振り切れることがある。** m4a に対して afade を掛けて AAC で
書き直したら、-0.9dB だったピークが 0.0dB に達した。一度 WAV に落として測り直し、
-1dB に合わせてから1回だけ AAC 化する。

## 検品は7本まとめて、毎回同じ形でやる

1本直したら、**同じ工程で作った全部を測り直す**。今回 r4 の誤読は、オーナーが耳で気づいて
初めて分かった（その前の r1 の切れ際も、r2 の問い合わせから全本を測って見つけた）。

```bash
# 全7本を文字起こしして、称号の読みが崩れていないか見る
for k in start r0 r1 r2 r3 r4 r5; do
  ffmpeg -y -v error -i assets/voice/shiori_$k.m4a -ar 16000 -ac 1 /tmp/v_$k.wav
done
# → tools/Irodori-TTS で whisper-small（docs/MEDIA.md の手順）
```

**漢字の当て方の違いで落とさない。** r3 は `闇よの羽根て` と起こされたが、読みは
「やみよのはねて」で正しい。判定は**音**で行い、漢字表記は見ない。
